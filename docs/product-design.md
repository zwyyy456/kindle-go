# Kindle Toolbox 产品设计与功能需求

状态：v1 产品基线已确认

确认日期：2026-07-16

## 1. 产品定位

Kindle Toolbox 是一个本地运行、面向可信局域网的 Kindle 内容工具箱。它首先服务个人使用，同时保持清晰的配置、数据边界和安装方式，以便后续开源给其他用户使用。

Web UI 的核心价值是：

- 将中文 TXT 制作为 EPUB 或原生 AZW3。
- 将可重排文本 EPUB 转换为原生 AZW3。
- 可选调用本机后台模型校对 TXT 或 EPUB。
- 管理原始文件、校对结果和多次生成的电子书产物。
- 通过适合 Kindle 浏览器的局域网页面下载成品。

Kindle 生词本导出属于独立 CLI 产品线，不进入 Web UI v1。

## 2. 产品原则

### 2.1 本地优先

- 书库、任务状态、模型校对状态和产物都保存在本机。
- 管理 Web UI 和 Kindle 下载页均可在可信局域网内访问。
- v1 不提供账号、登录、权限、云同步或公网部署方案。

### 2.2 原始文件不可变

- 导入后将文件复制到书库，并计算 SHA-256。
- 书库内的原始文件永久只读，不被转换或校对流程覆盖。
- 校对产生新的修订 TXT 或修订 EPUB。
- 格式生成产生独立 EPUB/AZW3 产物。

### 2.3 校对可选

- 用户可以直接转换，不必先运行 AI 校对。
- 校对是可恢复的后台任务，不是格式生成的前置条件。
- 不确定的修改默认保留原文。

### 2.4 书库为中心

- Web UI 首页是书库，而不是一次性转换表单。
- 一本书长期关联原始文件、校对任务、修订文件、生成任务和多个产物。
- v1 不引入“整理草稿”、内容分支或版本合并概念。

## 3. 产品边界

### 3.1 Web UI v1 包含

- TXT/EPUB 导入与哈希重复检测。
- TXT 转换预览。
- EPUB 结构读取与 AZW3 兼容性检查。
- TXT 到 EPUB/AZW3 的后台生成。
- EPUB 到 AZW3 的后台生成。
- TXT/EPUB 的可选 AI 校对和候选复核。
- 修订 TXT/EPUB、报告和审计记录管理。
- 多产物管理与 Kindle 局域网下载。
- 全局转换、模型和 Kindle 页面设置。

### 3.2 v1 不包含

- Kindle 生词本 Web UI。
- 多用户、账号、权限和云同步。
- 公网托管和远程访问方案。
- 除 Codex CLI 以外的模型后端实现。
- 完整 TXT/EPUB 正文编辑器。
- 自动识别并合并同一本书的不同版本。
- 内容版本分支、合并或所见即所得 EPUB 编辑。
- DRM EPUB、固定布局 EPUB 或复杂交互内容编辑。
- 书库回收站。

## 4. 当前实现与目标状态

本文描述的是 Web UI v1 目标，不代表所有功能当前已经完成。

| 能力 | 当前实现 | v1 目标 |
| --- | --- | --- |
| TXT 转换 | CLI 和同步 Web 转换 | 自动预览、后台生成、多产物 |
| EPUB 转换 | 原生 EPUB → AZW3 | 导入时兼容性报告、后台生成 |
| 书库 | 原文件加一个最新输出 | 书籍、任务、修订文件和多产物 |
| AI 校对 | 独立 TXT/EPUB Skill 与脚本 | 后台任务、进度和复核 Web UI |
| 任务恢复 | 校对脚本具备断点状态 | 统一持久化任务模型 |
| Kindle 页面 | 基础下载列表 | 最新 AZW3 与可选 EPUB |
| 生词本 | 独立 CLI happy path | 继续保持独立 CLI |

## 5. 信息架构

### 5.1 书库首页

- 导入 TXT 或 EPUB。
- 展示书名、源格式、导入时间、校对状态和最新产物。
- 支持按名称搜索，并按时间、名称和状态筛选或排序。
- 点击书籍进入详情页。
- 文件 SHA-256 与已有源文件相同时，提示用户选择打开已有书籍或仍然作为新书导入。
- 不根据文件名、书名或作者自动合并。

### 5.2 书籍详情页

- 展示和下载只读原始文件。
- TXT 展示章节与文本处理预览。
- EPUB 展示结构与 AZW3 兼容性检查结果。
- 提供“直接生成”和“开始校对”两个主要入口。
- 展示校对任务进度、候选复核和校对报告。
- 展示修订 TXT/EPUB。
- 展示所有 EPUB/AZW3 产物及其来源和参数。
- 展示任务失败原因，并允许重试。
- 删除整本书及其书库内数据。

### 5.3 任务页面

- 展示等待中、执行中、已暂停、已中断、已取消、已失败和已完成的任务。
- 展示任务类型、书籍、进度、创建时间和最近错误。
- 支持取消、恢复或重试适用的任务。
- App 重启后保留任务和队列状态。

### 5.4 设置页面

- 书库目录和服务监听地址。
- TXT 全局转换默认值。
- Kindle 页面 EPUB 展示开关。
- Codex CLI 可用性、默认模型、批次大小和并发数。
- 运行环境和外部依赖诊断。

### 5.5 Kindle 下载页

- 使用简单、低资源占用的 HTML，兼容 Kindle 浏览器。
- 默认每本书只展示最新 AZW3。
- 全局“展示 EPUB”开关默认关闭。
- 开启后，每本书同时展示最新 AZW3 和最新 EPUB，供 KOReader 等阅读器使用。
- 历史产物不在首页平铺；桌面 Web UI 始终展示全部产物。

## 6. 核心用户流程

### 6.1 TXT 直接生成

```text
导入 TXT
  → 计算哈希并检测编码
  → 自动运行只读转换预览
  → 查看目录和文本处理统计
  → 可选调整本次转换参数
  → 选择 EPUB、AZW3 或两者
  → 后台生成并下载
```

TXT 预览和生成使用同一套解析逻辑。章节识别、断行合并、空行处理、删除/替换规则都发生在转换过程中，不产生独立的“整理版”。

### 6.2 TXT 校对后生成

```text
导入 TXT
  → 启动 AI 校对
  → 后台分批初审和隔离复核
  → 人工处理歧义候选
  → 生成修订 TXT
  → 对修订 TXT 运行转换预览
  → 后台生成 EPUB/AZW3
```

### 6.3 EPUB 直接生成

```text
导入 EPUB
  → 计算哈希
  → 读取元数据、封面、spine、目录和资源
  → 执行 AZW3 兼容性检查
  → 检查通过后后台生成 AZW3
```

EPUB 已有 spine 和目录，不运行 TXT 章节识别、断行合并或删除/替换规则。

### 6.4 EPUB 校对后生成

```text
导入 EPUB
  → 启动 AI 校对
  → 后台校对阅读顺序文本和正文引用图片
  → 人工处理歧义候选
  → 生成修订 EPUB
  → 重新执行兼容性检查
  → 后台生成 AZW3
```

## 7. TXT 转换需求

### 7.1 默认界面

- 书名、作者和语言。
- 输出格式：EPUB、AZW3 或两者；默认只选择 AZW3。
- 是否生成文字封面。
- 自动生成的目录预览。
- 编码、章节、段落、删除行、空行和断行合并统计。
- 生成与开始校对操作。

同时选择 EPUB 和 AZW3 时创建两个独立生成任务。一个格式失败不得影响另一个格式已经成功的结果。

### 7.2 高级设置：章节与文本处理

- 一级章节正则和二级章节正则。
- 拆分层级。
- 是否合并断行和压缩连续空行。
- 删除规则列表和替换规则列表。

修改后可以刷新目录与处理统计预览。

### 7.3 高级设置：排版

- 行高、首行缩进、段落间距和对齐方式。
- 行高控制同一段落内文字行的行间距；段落间距控制段落间额外空白。
- 默认值：行高 `1.7`、首行缩进 `2em`、段落间距 `0`、两端对齐。

### 7.4 配置规则

- 新预览和转换从全局默认配置开始。
- 书籍详情页的修改默认只影响本次预览和生成。
- 只有显式点击“保存为全局默认值”才更新全局配置。
- 不为每本书维护长期转换配置。
- 每个成功产物保存本次实际使用的完整参数快照。

## 8. EPUB 兼容性检查

导入 EPUB 后自动执行只读检查，至少展示：

- 标题、作者、语言、标识符和封面。
- spine 文档数量和读取顺序。
- EPUB2 NCX 或 EPUB3 nav 目录。
- 正文引用的本地 CSS、JPEG、PNG 和 SVG。
- 内部链接、脚注和目录目标有效性。
- 不受支持的 XHTML、资源类型、远程资源或复杂 CSS 问题。

检查失败时必须定位到具体文档、资源或引用。检查未通过时不启用 AZW3 生成。修订 EPUB 也必须重新执行同一套检查。

## 9. AI 校对需求

### 9.1 模型后端

- v1 只支持本机已登录的 Codex CLI。
- Web UI 不保存模型 API Key。
- 设置页检测 Codex 是否安装并可用。
- 用户可配置默认模型、批次大小和并发数。
- 内部保留可替换的模型后端接口，但 v1 不实现其他供应商。

### 9.2 审阅规则

- 每个非重叠正文范围都必须完成第一轮模型审阅。
- 每个候选都必须使用隔离上下文完成第二轮验证。
- 两轮均为高置信度且替换内容完全一致时自动应用。
- 低置信度、不一致、歧义和风格类候选进入人工复核。
- 自动应用项仍必须出现在报告和审计记录中。
- 用户可以接受、拒绝或修改待复核候选的替换文本。
- v1 不提供完整正文编辑器。

### 9.3 未决候选

- 未决候选默认保持原文。
- 未决候选不阻塞修订 TXT/EPUB 生成。
- 生成前明确显示未决数量并要求一次确认。
- 修订文件和报告标记“完整”或“存在未决项”。
- 用户完成更多复核后可以再次生成新的修订文件。

### 9.4 校对并发和恢复

- 全局同一时间只运行一本书的 AI 校对。
- 其他校对任务按 FIFO 顺序等待。
- 单本书内部可以按全局并发设置并行处理批次。
- App 重启后从最后完成的批次继续。
- 取消或失败不得删除已经完成的批次、复核和审计状态。

## 10. 后台任务

### 10.1 任务类型

- AI 校对。
- 修订 TXT/EPUB 生成。
- EPUB 生成。
- AZW3 生成。

TXT 预览和 EPUB 兼容性检查是快速只读操作，可以同步执行，不进入长任务队列。

### 10.2 状态

```text
等待中 → 执行中 → 已完成
             ├── 已暂停
             ├── 已中断
             ├── 已取消
             └── 已失败
```

### 10.3 持久化和失败处理

- 任务、队列顺序和进度必须持久化。
- AI 校对支持按批次断点续跑。
- 格式生成被进程中断后标记为“已中断”，用户重试时从头生成。
- EPUB/AZW3 使用临时文件写出，成功后原子移动为正式产物。
- 失败或中断任务不得产生可下载的正式产物。
- 错误信息需要面向用户说明具体阶段和原因。

## 11. 书籍、文件与产物

```text
书籍
├── 只读原始 TXT/EPUB
├── TXT 预览或 EPUB 兼容性检查
├── 校对任务、候选、报告和审计记录
├── 可选修订 TXT/EPUB
├── 转换任务
└── 多个 EPUB/AZW3 产物
```

每个产物至少记录：

- 格式、文件名、大小和创建时间。
- 来源是原始文件还是某个修订文件。
- 完整转换参数快照。
- 对应生成任务。
- 来源校对结果是否仍有未决项。

默认突出最新 EPUB 和最新 AZW3，旧产物继续保留，并允许下载或手动删除。

## 12. 删除规则

删除一本书时，同时删除书库内的：

- 原始文件副本。
- 修订 TXT/EPUB。
- 校对状态、候选、报告和审计记录。
- 全部 EPUB/AZW3 产物。
- 相关后台任务记录。

删除前必须展示范围并二次确认。存在运行中任务时禁止删除，用户必须先取消任务。用户导入前的外部原始文件不受影响。v1 不提供回收站。

## 13. v1 验收场景

### 13.1 TXT 直接转换

- 导入 TXT 后可以看到编码、目录和文本处理统计。
- 修改高级设置后预览同步更新。
- 可以单独或同时生成 EPUB/AZW3。
- 产物可从桌面 Web UI 下载，最新 AZW3 可从 Kindle 页面下载。

### 13.2 EPUB 直接转换

- 导入后可以看到元数据、目录和兼容性结果。
- 不兼容问题能定位到具体文档或资源。
- 检查通过的 EPUB 可以后台生成 AZW3。

### 13.3 校对闭环

- TXT/EPUB 校对可以排队、显示进度并在重启后继续。
- 双重高置信度修改自动应用，歧义项可人工复核。
- 存在未决项时可以确认保留原文并生成修订文件。
- 修订文件、报告和审计记录均可下载。
- 修订文件可以继续用于 EPUB/AZW3 生成。

### 13.4 书库和任务可靠性

- 相同哈希再次导入时由用户决定打开已有书籍或重复导入。
- 多次生成的成功产物都被保留，失败任务不污染产物列表。
- App 重启后任务、队列、书籍和产物状态保持一致。
- 删除书籍时完整清理书库内关联数据，不影响外部原文件。

### 13.5 Kindle 下载

- 默认只显示每本书最新 AZW3。
- 开启全局 EPUB 开关后，同时显示最新 EPUB。
- 页面可在 Kindle 浏览器中完成浏览和下载。
